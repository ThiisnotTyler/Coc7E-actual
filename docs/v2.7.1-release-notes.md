# CoC 7e LLM Keeper — v2.7.1 "The Aura-Farming Patch"

Release notes, July 20, 2026. Covers v2.7.0 -> v2.7.1 (dice integrity). All
changes verified offline: test_engine.py 182 checks + test_charcreate.py 64
checks, both ALL TESTS PASSED, plus fresh-extraction verification of the
shipped zip. Every fix below has a regression test written before the fix.

## 1. The field log that forced this patch

First live session on tallow-chapel, solo investigator (Jane Doe), k2.6
default tier:

1. *"I sneak up to the side and attempt to climb onto the balcony"* — the
   preroll net (search/listen/combat verbs only) matched nothing. The turn
   went to the model with an empty DICE RESULTS block, and the model
   narrated the climb's success by fiat. No roll ever happened.
2. The model then asked for a roll the only way it knew how — prose:
   *"Roll Locksmith (target 60)"*. The response schema has had a
   `dice_requests` channel since v2.2; the engine never read it. The player
   typed `roll!`; the next turn again carried zero dice.
3. Holding no dice for the second time, the model improvised: Jane
   *"suddenly drops and rolls hard across the grit-slick flagstones"* — an
   action-hero entrance the player never declared, during what was meant to
   be a sneaky infiltration. (The player's verdict: "I was aura farming.")
4. Separately: the model's option menu leaked its own design notes —
   "(safe, slow)", "(risky, rewarding)", "(advances the danger)" — because
   the system prompt literally described the options that way.

## 2. Root causes and fixes

### 2.1 The preroll net was three verbs wide

`keeper._preroll` matched only search/spot, listen, and combat patterns.
Everything else — sneaking, climbing, lock-picking, fast-talking — went to
the model undecided. The net is now a compiled regex table over the risky
7e skills: Stealth, Climb, Jump, Swim, Throw, Locksmith, Sleight of Hand,
Disguise, Dodge, Intimidate, Charm, Fast Talk, Persuade, First Aid, Track,
Drive Auto, Library Use. Targets come from the investigator's skills, else
the 7e base values (charcreate's own table; Dodge = DEX/2). Existing
search/listen/combat priority is unchanged.

### 2.2 The engine ignored `dice_requests`

`take_turn` now harvests `dice_requests` from every model response into
`pending_rolls` (validated: known character, named skill, optional explicit
target). On the following turn:

- A roll affirmation (`roll!`, `yes`, `go ahead`, `do it`, ...) resolves the
  request through the real dice engine — result lands in DICE RESULTS for
  the model, and on screen for the player.
- A clearly different declaration abandons the stale request (the moment
  passed) and prerolls the new action normally.
- Turns where only OTHER investigators act leave the request queued.
- Pending rolls persist in the save file, so quit-before-rolling resumes
  mid-cliffhanger.

### 2.3 Rolls were invisible to the table

Every engine roll is announced before the model is queried:

```
» Jane Doe — Locksmith 60%: rolled 34 — Regular success   (requested: jimmy the window quietly)
```

Combat results reuse the same line (with damage), and note-only outcomes
(no reachable target, malfunctions) print their notes.

### 2.4 The system prompt taught the leaks

Three rules added, all pinned by tests:

- Un-rolled risky outcomes are "NOT yours to narrate" — narrate the setup,
  put the roll in `dice_requests`.
- Roll requests live "ONLY in dice_requests" — never in narration or
  required_actions prose.
- Options are presented as pure fiction; "NEVER tag options with
  meta-labels". The pacing structure (cautious / bold / move a Front)
  survives as guidance; the labels do not ship to the table.

## 3. Latency corollary: default budget back to 8192

The same log showed k2.6's initial 4096-token calls returning EMPTY
(`finish_reason=length`) on 2 of 5 rich turns — 51.5s and 81.7s of dead air
before the 8192 strict-retry succeeded. The v2.6.0 diet was aimed at k3's
sprawl; k3 has had its own `max_output_tokens_heavy` knob since v2.7.0. The
default tier returns to the budget the field measured as sufficient.
`--report` will tell us if the empty-initial rows disappear.

## 5. Upgrade

Merge the zip's inner `coc7-keeper` over your folder, run both suites. Your
key, saves, roster, and chronicle survive (never in the zip). If you keep a
hand-maintained `config/settings.json`, bring over `max_output_tokens: 8192`
and re-copy `config/system-prompt.txt` — the three new narration rules live
there, and the file is safe to replace (no per-user content).

*Keeper's note. The dice were always rolled behind the screen. Now they are
rolled in front of it — and a Keeper who asks for a roll has to wait for it
like everyone else.*
