CoC 7e LLM Keeper — v2.6.0 Release Notes

Covers v2.5.0 → v2.6.0 (diagnostics, cost control, presence). All changes verified offline: 116 engine checks + 64 creation-wizard checks green, plus fresh-extraction verification of the shipped zip.

1. What this release is

v2.6.0 closes the loop on the question that started the v2.5 line: “why is a turn slow, and where does the money go?” v2.5 built the instruments (per-attempt timing log, --debug console mode, latency benchmark). v2.5.1 acted on the first field report (solo parties were silently routed to the premium model every turn). v2.6.0 acts on the second: it puts a live, thematic wait indicator on long calls and puts the token budget on a diet. Every claim below is backed by the project’s own timing log.

  • No retry storm. Both game turns and both benchmark calls succeeded on the first attempt. The three-strike retry ladder was exonerated by data.
  • The solo k3 trap (root cause of “3–4 minute turns”). SQUAD mode requires 3+ investigators; a one-character party is therefore always INDIVIDUAL, and INDIVIDUAL always escalated to the heavy tier.   • Provider hiccup caught, handled. One turn failed three times in under a second with empty (finish_reason=length) — an instantaneous, transient provider-side rejection. The ladder refunded the turn; the session never crashed.
  • Budget invited sprawl. An 8,192-token output budget versus ~400–900 visible tokens actually used left room for hidden-reasoning overruns on long calls.

3. New in v2.6.0

3.1 Thematic loading presence

The API call is blocking and non-streaming, so a 200-second turn used to look like a hung terminal. Long calls now paint a single self-erasing line — spinner, live timer, rotating Keeper flavor:

|  34.0s — Something shifts behind the walls...
  • Appears only after 1.5 s — instant calls stay silent.
  • Never fires in --mock mode or when output is redirected (CI-safe).
  • Cannot crash a session: the animator is a daemon thread wrapped in total failure tolerance.
  • Disable with "llm": {"loading_bar": false}.

3.2 Token-budget diet

llm.max_output_tokens default lowered 8192 → 4096. Routine generations use under a quarter of the old budget; the excess was headroom for hidden thinking, not narration. If a call ever truncates (finish_reason=length), the existing ladder retries at 2×/4× automatically — the recovery ceiling is unchanged, the routine cost is not.

3.3 Carried forward from v2.5.x

  • logs/llm_timing.jsonl — every attempt recorded (model, tier, attempt, budget, sizes, seconds, error).
  • --debug — the same lines echoed live during play.
  • test_latency.py — paid two-call benchmark; --report — free offline analysis.
  • llm.heavy_escalation — individual (legacy) / combat (recommended solo) / never.
