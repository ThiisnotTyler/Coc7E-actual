# CoC 7e LLM Keeper — v2.7.4 "The Flaky-Die Patch"

Release notes, July 20, 2026. Covers v2.7.3 -> v2.7.4 (deterministic tests +
malfunction visibility). Verified offline: test_engine.py ~205 checks (the
dice section's conditional d100 assertion varies the count by design) +
test_charcreate.py 64 checks, both ALL TESTS PASSED, five consecutive green
runs, plus fresh-extraction verification of the shipped zip.

## 1. The field report

`py test_engine.py` failed on the maintainer's machine at:

    FAIL: a shotgun fires on Firearms_Rifle_Shotgun, not the handgun base

The same zip passed every run on the build side. The check fired a real
d100; the 12-gauge's malfunction threshold is 96 — a 4% chance per shot.
On a jam, `resolve_attack` returned early carrying only `roll` and a note:
no `target`, no `level`. The assertion wanted both. One machine rolled
snake eyes; the assertion was a coin flip that had simply been winning.

## 2. Fixes

### 2.1 The jam path keeps the attempt visible (engine)

`resolve_attack` now records `roll`/`target`/`level` BEFORE the malfunction
branch. A jam is a real outcome of a real attempt — the DICE RESULTS block
and the table display should say what was tried:

    » Tyler Moss — Firearms Rifle Shotgun 50%: rolled 97 — Fumble — WEAPON JAMS

### 2.2 Deterministic skill-selection tests (suite)

Checks that pin *which* skill rolls stub the keeper's dice
(`skill_check = lambda target: (42, "Regular")`), plus a forced-jam
regression (`(97, "Fumble")`) that pins malfunction visibility itself.
Luck-based assertions only ever assert what luck can't change.
