# CoC 7e LLM Keeper — v3.0 Architecture Proposal
## Multi-Scene, Multi-Player, Engine-Heavy Distributed TTRPG Server

**Status:** Draft — pending v2.2 field testing  
**Author:** Kimi K3 (architecture) + User (requirements)  
**Date:** 2026-07-18

---

## 1. Philosophy

**The LLM narrates. The engine governs.**

Every system that can be deterministic—pacing, state tracking, memory, procedural generation, cross-scene synchronization—must be. The LLM only handles creative synthesis: turning structured game state into evocative prose.

This document proposes a complete architectural overhaul from v2.2's single-terminal loop to a multi-tenant, multi-scene, async server. Each proposal is derived from classic game design (MUDs, L4D, Dwarf Fortress, Disco Elysium, RimWorld) and optimized for minimal LLM context, maximal narrative coherence.

---

## 2. Core Principles

| Principle | Rationale |
|-----------|-----------|
| **Scene autonomy** | Each scene runs its own turn pacing. Combat scenes tick fast; exploration scenes tick slow. No global blocking. |
| **Per-player views** | Each terminal receives only what their character perceives. The LLM never sees full world state. |
| **Event-driven sync** | Cross-scene effects propagate via an event bus, not via LLM awareness. |
| **Deterministic procedural** | All randomness is seeded. Campaigns are replayable from `seed + action_log`. |
| **Ghost turns** | Idle players don't block the world. The engine derives a default action. |
| **Context compression** | Reduce LLM tokens per call by 60–80% via structured state, not by reducing calls. |

## 3. New Module Proposals

### 3.1 `src/turn_manager.py` — Global Turn Manager

**Stolen from:** MUD tick systems + Dwarf Fortress time dilation

**Purpose:** Async, per-scene turn scheduling. Each scene has its own pacing multiplier. Characters act when their scene ticks, not when a global round passes.

**Key Classes:**

```python
class TurnPacing(Enum):
    COMBAT = "combat"      # 1 unit per turn (~3 seconds)
    TENSE = "tense"        # 0.1 units per turn (~30 seconds)
    EXPLORATION = "exploration"  # 0.02 units per turn (~5 minutes)
    DOWNTIME = "downtime"  # 0.005 units per turn (~1 hour)

@dataclass(order=True)
class ScheduledAction:
    execute_at: float   # global timestamp
    char_id: str
    action_type: str    # "declare", "resolve", "event"
    priority: int = 0   # combat beats exploration at same timestamp

class GlobalTurnManager:
    def __init__(self): ...
    def set_scene_pacing(self, scene_id: str, pacing: TurnPacing): ...
    def schedule(self, char_id: str, action_type: str, delay: float = 0, priority: int = 0): ...
    def tick(self) -> Optional[ScheduledAction]: ...
    def get_pending_for_scene(self, scene_id: str) -> List[ScheduledAction]: ...
```

**Integration Points:**
- Called by `keeper.py` after each state delta to schedule next actions
- Consumed by `terminal_server.py` to know when to prompt each player
- Used by `scene_director.py` to determine when to cut between scenes

**Test Requirements:**
- Two scenes at different paces: combat scene resolves 10 turns while exploration scene resolves 1
- Priority queue ordering: combat actions resolve before exploration actions at same timestamp
- Ghost turn scheduling: idle characters get auto-scheduled after timeout

### 3.2 `src/view_compiler.py` — Per-Player View Compiler

**Stolen from:** MUD room descriptions + MMO client culling

**Purpose:** Deterministic filtering of global state into what a single character perceives. The LLM prompt is built from this view, not from raw world state.

**Key Classes:**

```python
@dataclass
class PlayerView:
    char_id: str
    scene_id: str
    scene_name: str
    scene_description: str          # cached LLM output, refreshed on scene change
    visible_exits: Dict[str, dict]  # filtered by skills/flags
    visible_characters: List[dict]   # same scene + line of sight
    audible_events: List[dict]     # from adjacent scenes via sound propagation
    known_flags: List[str]         # global flags this character knows
    personal_tags: List[str]        # belief tags for private narration
    available_actions: List[str]    # derived from state
    turn_prompt: str                # "What do you do?" or "Combat continues..."

class ViewCompiler:
    def __init__(self, world_state, spatial_engine, belief_engine): ...
    def compile_view(self, char_id: str) -> PlayerView: ...
    def _filter_exits(self, scene: Location, char: Character) -> Dict[str, dict]: ...
    def _obscure_event(self, event: dict, quality: str) -> str: ...
    def _derive_available_actions(self, char: Character) -> List[str]: ...
```

**Critical Rule:** Never expose exact HP/SAN of other characters unless a skill check (Spot Hidden, Psychology) passes. Never expose scene contents beyond perception range.

**Integration Points:**
- Called by `terminal_server.py` before every player prompt
- Called by `prompt_compiler.py` to build LLM context
- Uses `spatial_engine.can_hear()` and `spatial_engine.get_perception_level()`

**Test Requirements:**
- Character in basement sees only basement contents + muffled upstairs sounds
- Character with `Spot_Hidden` 60 sees hidden exit that character with 25 does not
- Dying character's view compiler shows fewer available actions

### 3.3 `src/event_bus.py` — Cross-Scene Event Bus

**Stolen from:** L4D AI Director's global intensity propagation + MUD event systems

**Purpose:** Publish events from one scene to all perceptible scenes. The LLM in Scene B doesn't "know" about Scene A's gunshot—the engine injects it as an `audible_event` in Scene B's view.

**Key Classes:**

```python
class EventType(Enum):
    SOUND = "sound"          # 1=whisper, 2=conversation, 3=shout, 4=gunshot, 5=explosion
    VISUAL = "visual"        # 0=none, 1=subtle, 2=obvious, 3=blinding
    MAGIC = "magic"          # Mythos resonance, affects SAN at distance
    PHYSICAL = "physical"    # Structural damage
    SOCIAL = "social"        # NPC movement, attitude changes
    PLOT = "plot"            # Front clock advances

@dataclass
class WorldEvent:
    event_id: str
    event_type: EventType
    source_scene: str
    source_char: Optional[str]
    noise_level: int
    visual_magnitude: int
    mythos_resonance: int
    description: str
    mechanical_effects: List[dict]
    propagates_through: List[str] = None
    decays_at_distance: bool = True

class EventBus:
    def __init__(self, spatial_engine): ...
    def publish(self, event: WorldEvent): ...
    def _calculate_propagation(self, event: WorldEvent) -> List[str]: ...
    def _notify_character(self, char_id: str, event: WorldEvent, scene_id: str): ...
```

**Propagation Rules:**
- Sound attenuates by connection type (door: -1, wall: -2, stairs: -1, open: 0)
- Visual blocked by walls, attenuated by distance
- Mythos resonance ignores physical barriers, attenuates by `distance * 2`
- Events decay: only last 3 turns in scene memory

**Integration Points:**
- Called by `keeper.py` after state delta application
- Consumed by `view_compiler.py` to build `audible_events`
- Triggers SAN rolls via `sanity_engine` for mythos events at distance

**Test Requirements:**
- Gunshot in basement (noise=4) heard muffled upstairs, not heard outside
- Mythos ritual (resonance=3) causes SAN roll in adjacent room even with walls
- Event decays: after 3 turns, no longer appears in scene memory

### 3.4 `src/director.py` — Keeper Director (Intensity Pacing)

**Stolen from:** L4D AI Director (GDC 2009 slides)

**Purpose:** Four-state FSM modulates narrative tension per scene. The LLM receives `director_state` + `narrative_guidance` and doesn't decide pacing.

**Key Classes:**

```python
class DirectorState(Enum):
    BUILD_UP = "build_up"          # Escalate tension
    SUSTAIN_PEAK = "sustain_peak"  # Maintain pressure, no reprieve
    PEAK_FADE = "peak_fade"        # Danger resolves, aftermath tense
    RELAX = "relax"                # Safe moment for investigation/recovery

class KeeperDirector:
    def __init__(self, config: dict): ...
    def update(self, turn_delta: dict): ...
    def _transition_state(self): ...
    def get_scene_pressure(self, scene_id: str) -> dict: ...
    def _narrative_guidance(self, state: DirectorState) -> str: ...
```

**State Transitions:**
- BUILD_UP → SUSTAIN_PEAK when `global_intensity >= peak_threshold` (default 0.7)
- SUSTAIN_PEAK → PEAK_FADE after 3–5 turns of sustained pressure
- PEAK_FADE → RELAX when intensity drops below `peak_threshold * 0.5`
- RELAX → BUILD_UP after `relax_duration` turns (default 5)

**Per-PC Intensity Tracking:**
- HP loss: `abs(delta) / max_hp * 0.3`
- SAN loss: `abs(delta) / max_san * 0.4`
- Major wound: `+0.5`
- New threat discovered: `+0.3`
- Natural decay: `-0.05` per turn if not in combat

**Integration Points:**
- Called by `keeper.py` after each turn's state delta
- Consumed by `prompt_compiler.py` as `director_state` field
- Used by `arc_weaver.py` to coordinate major plot beats with intensity

**Test Requirements:**
- Combat scene reaches SUSTAIN_PEAK after 2 turns of damage
- Relaxation scene stays in RELAX for exactly 5 turns before BUILD_UP
- Intensity decays naturally when combat ends

### 3.5 `src/arc_weaver.py` — Campaign Arc Weaver

**Stolen from:** RimWorld storyteller system

**Purpose:** Pre-generates major plot events from campaign seed. The engine knows the whole campaign structure; the LLM only knows what's foreshadowed.

**Key Classes:**

```python
class KeeperPersonality(Enum):
    CASSANDRA = "cassandra"  # Steady escalation, fair but relentless
    PHOEBE = "phoebe"        # Long calm, then intense spikes
    RANDY = "randy"          # Chaotic, unpredictable
    MYTHOS = "mythos"        # SAN threats escalate independently of physical danger

class ArcWeaver:
    def __init__(self, personality: KeeperPersonality, campaign_seed: str,
                 expected_sessions: int = 3, expected_turns_per_session: int = 15): ...
    def _generate_event_schedule(self): ...
    def get_events_for_turn(self, turn: int) -> List[dict]: ...
    def get_upcoming_foreshadow(self, turn: int, horizon: int = 5) -> List[dict]: ...
```

**Event Types:**
- `clue_discovery`: Reveals plot point
- `npc_betrayal`: Shifts NPC attitude
- `mythos_revelation`: SAN event + mythos gain
- `physical_threat`: Combat encounter
- `sanity_event`: Isolation, hallucination, dream sequence

**Foreshadowing Protocol:**
- Events within `horizon` turns inject `upcoming_pressure` into LLM prompt
- LLM is told to "increase atmospheric tension" without knowing specifics
- Actual event triggers on schedule, not when LLM decides

**Integration Points:**
- Initialized at campaign start with campaign seed
- Called by `keeper.py` at turn start to check for scheduled events
- Consumed by `prompt_compiler.py` as `upcoming_events` field

**Test Requirements:**
- Cassandra personality distributes events evenly across 45 turns
- Mythos personality maintains separate physical and SAN threat tracks
- Foreshadowing appears in prompts 5 turns before event, not after

### 3.6 `src/belief_engine.py` — Belief System (Disco Elysium-Style)

**Stolen from:** Disco Elysium Thought Cabinet

**Purpose:** Characters accumulate narrative "lenses" that mechanically alter their perception. The engine tracks belief stages; the LLM applies perception filters.

**Key Classes:**

```python
@dataclass
class Belief:
    id: str
    name: str
    description: str
    trigger_tags: Set[str]      # What events advance this belief
    current_stage: int = 0
    max_stages: int = 3
    stage_modifiers: Dict[int, dict]  # Per-stage LLM prompt modifiers

class BeliefEngine:
    def __init__(self): ...
    def check_triggers(self, turn_events: List[dict], pc_id: str): ...
    def get_private_modifiers(self, pc_id: str) -> Dict[str, dict]: ...
```

**Example Belief: "The House is Watching Me"**
- Trigger: Multiple `Spot_Hidden` failures in Corbitt House
- Stage 1: "Floorboards seem to remember your weight"
- Stage 2: "The house leans toward you when unobserved"
- Stage 3: "You are certain the house is alive. Others are blind."

**Perception Filters:**
- `perception_filter`: What the LLM adds to descriptions
- `narrative_bias`: How the LLM interprets ambiguous events
- `available_insights`: Secret details only this character notices

**Integration Points:**
- Called by `keeper.py` after state delta to check for belief advances
- Consumed by `view_compiler.py` as `personal_tags`
- Applied by `prompt_compiler.py` to `private_narrations` field

**Test Requirements:**
- Belief advances after 3 trigger events, not before
- Stage 2 modifier appears in private narration but not public
- Multiple beliefs stack: all applicable filters apply

### 3.7 `src/encounter_deck.py` — Structured Encounter Deck

**Stolen from:** FTL Faster Than Light event system

**Purpose:** Replace random tables with structured decks. Enables "deck manipulation" mechanics (scry, rig, banish).

**Key Classes:**

```python
class EncounterDeck:

    def _build_decks(self, config: dict): ...
    def draw(self, deck_name: str, turn: int, context_flags: dict) -> dict: ...
    def manipulate(self, deck_name: str, action: str, target_card_id: str = None): ...
```

**Deck Types:**
- `COMBAT`: Wandering monsters, ambushes
- `SANITY`: Isolation effects, hallucinations, dreams
- `CLUE`: Discoverable items, hidden passages, documents
- `SOCIAL`: NPC encounters, random conversations
- `ENVIRONMENTAL`: Weather, structural events, animal sounds

**Card Properties:**
- `copies`: How many in deck (1=unique, 3=common)

**Integration Points:**
- Called by `keeper.py` when random encounter/clue check triggers
- Consumed by `prompt_compiler.py` as `encounter_result` field
- Used by `chronicle_seed.py` for deterministic draws

**Test Requirements:**
- Deck shuffles when empty, not before
- Conditional cards only appear when flags met
- Unique cards (copies=1) removed permanently when drawn

### 3.8 `src/action_grammar.py` — Structured Action Parser

**Stolen from:** Classic MUD command parsers

**Purpose:** Convert free-text player input into structured actions before reaching the LLM. Reduces ambiguity, enables mechanical pre-derivation.

**Key Classes:**

```python
class ActionParser:
    INTENT_PATTERNS = {
        "investigate": r"(search|look|examine|inspect|study|read|check)",
        "move": r"(go|walk|enter|leave|head|climb|descend|approach|retreat)",
        "attack": r"(attack|shoot|stab|punch|fight|kill|ambush|strike)",
        "talk": r"(talk|ask|persuade|intimidate|question|demand|plead)",
        "use": r"(use|activate|drink|eat|read|cast|play)",
        "hide": r"(hide|sneak|conceal|crouch|duck)",
        "flee": r"(flee|run|escape|retreat|bolt|dash)",
        "assist": r"(help|heal|aid|rescue|protect|support|carry)",
        "observe": r"(watch|listen|wait|stand guard|look out)",
    }
    
    MODIFIER_PATTERNS = {
        "carefully": r"(carefully|slowly|methodically|thoroughly)",
        "quickly": r"(quickly|fast|hurry|rush|immediately)",
        "quietly": r"(quietly|silently|stealthily|without a sound)",
        "loudly": r"(loudly|shout|yell|scream|bang)",
        "aggressively": r"(aggressively|violently|furiously|recklessly)",
        "cautiously": r"(cautiously|warily|hesitantly|suspiciously)",
    }

    def parse(self, raw_input: str, char_id: str, context: dict) -> dict: ...
    def _derive_mechanics(self, intent: str, modifier: str, target: dict,
                          tool: dict, context: dict) -> dict: ...
```

**Mechanical Derivation:**
- `investigate` + `carefully` → `Spot_Hidden` +1 bonus die
- `attack` + firearm → `Firearms_Handgun` combat roll
- `hide` + `quietly` → `Stealth` +1 bonus die, position → `behind_cover`
- `move` + no exit → fail, suggest available exits

**Integration Points:**
- Called by `terminal_server.py` on player input
- Consumed by `keeper.py` for pre-roll resolution
- Passed to `prompt_compiler.py` as structured action

**Test Requirements:**
- "I carefully search the room" → intent: investigate, modifier: carefully
- "shoot the ghoul" → intent: attack, target: ghoul, tool: equipped weapon
- Unparseable input → fallback to freeform with confidence 0.0

### 3.9 `src/chronicle_seed.py` — Deterministic Procedural Generation

**Stolen from:** Dwarf Fortress world generation

**Purpose:** All procedural elements seeded by `hash(campaign_seed + turn + element_type)`. Campaigns are replayable from seed + action log.

**Key Classes:**

```python
class ChronicleSeed:
    def __init__(self, campaign_seed: str): ...
    def get_seed(self, turn: int, element_type: str, salt: str = "") -> int: ...
    def random_encounter(self, turn: int, location_id: str, threat_level: int) -> dict: ...
    def npc_reaction(self, turn: int, npc_id: str, pc_id: str, context_tags: list) -> dict: ...
    def weather_event(self, turn: int, location_id: str, season: str) -> dict: ...
    def loot_generation(self, turn: int, container_id: str, loot_table: str) -> dict: ...
```

**Seed Formula:**
```python
raw = f"{campaign_seed}:{turn}:{element_type}:{salt}"
seed = int(hashlib.sha256(raw.encode()).hexdigest(), 16) % (2**32)
```

**Integration Points:**
- Initialized at campaign start
- Called by `encounter_deck.py` for deterministic draws
- Called by `keeper.py` for weather, loot, NPC reactions
- Enables full campaign reconstruction from `seed + action_log.json`

**Test Requirements:**
- Same seed + same turn + same element = same result
- Different salt = different result
- Full campaign reconstructible from seed + action log

### 3.10 `src/prompt_compiler.py` — Tiered Context Compiler

**Stolen from:** v2.2's existing compression + MUD prompt optimization

**Purpose:** Reduce LLM tokens per call by 60–80% via structured, tiered context. The LLM receives only what it needs for the current mode.

**Key Classes:**

```python
class ContextCompiler:
    def compile(self, char_id: str, mode: ResolutionMode) -> str: ...
    def _minimal_context(self, char_id: str) -> str: ...      # SQUAD: ~800 tokens
    def _standard_context(self, char_id: str) -> str: ...     # INDIVIDUAL: ~1500 tokens
    def _full_context(self, char_id: str) -> str: ...         # CINEMATIC: ~2500 tokens
```

**Context Tiers:**

| Tier | Mode | Includes | Tokens |
|------|------|----------|--------|
| Minimal | SQUAD | Scene + exits + active PCs + dice results + director state | ~800 |
| Standard | INDIVIDUAL | Above + visible NPCs + audible events + belief tags | ~1500 |
| Full | CINEMATIC | Above + full character summaries + recent history + arc foreshadowing | ~2500 |

**Compression Techniques:**
- `scene_description`: Cached until scene changes
- `character_summaries`: Only delta-updated characters
- `event_history`: Summarized to 1 line per event, max 5 events
- `belief_tags`: Compressed to `id:stage` format
- `flag_registry`: Only flags relevant to current scene

**Integration Points:**
- Called by `keeper.py` before every LLM query
- Consumed by `gemini_client.py` as the user prompt
- Uses `view_compiler.py` for per-player filtering

**Test Requirements:**
- Same world state produces same token count within 10%
- Scene cache refreshes only on scene change
- Full context never exceeds 3000 tokens

### 3.12 `src/delta_sync.py` — Resume/Reconnect Delta Protocol

**Stolen from:** MMO zone handoff protocols

**Purpose:** When a player reconnects, send only what changed since they were last active. Not full world state.

**Key Classes:**

```python
class DeltaSync:
    def __init__(self, world_state): ...
    def get_delta(self, char_id: str) -> dict: ...
    def _character_would_perceive(self, char_id: str, event: WorldEvent) -> bool: ...
    def _summarize_for_char(self, event: WorldEvent, char_id: str) -> str: ...
```

**Delta Contents:**
- `turns_missed`: Count
- `character_updates`: What changed about their character
- `scene_changes`: Scene they're in (may have changed while offline)
- `events_heard`: Events they would have perceived, summarized
- `plot_advances`: New plot points they would know about
- `belief_advances`: Any beliefs that evolved

**Integration Points:**
- Called by `terminal_server.py` on player reconnect
- Uses `event_bus.py` event history
- Uses `view_compiler.py` perception rules

**Test Requirements:**
- Player offline for 5 turns: delta contains exactly 5 turns of events
- Player in combat scene that resolved while offline: delta includes combat outcome
- Player in exploration scene that didn't change: delta is minimal

## 4. Modified Existing Modules

**Current:** Single-threaded turn loop, single scene, single LLM call per turn.

**Proposed:** Async multi-scene orchestrator. Receives actions from `terminal_server`, routes to `turn_manager`, compiles prompts via `prompt_compiler`, applies deltas, publishes events.

**New Methods:**

## 5. Data Flow: Complete Turn Cycle

```
┌─────────────────────────────────────────────────────────────┐
│  1. GLOBAL TURN MANAGER pops next ScheduledAction           │
│     → char_id="eleanor", scene="basement", time=15.3       │
└──────────────────┬────────────────────────────────────────────┘
                   │
┌──────────────────▼──────────────────────────────────────────┐
│  2. VIEW COMPILER builds PlayerView for Eleanor             │
│     → Scene: basement, exits, ghoul (hostile), muffled      │
│       footsteps upstairs, belief tags, available actions     │
└──────────────────┬────────────────────────────────────────────┘
                   │
┌──────────────────▼──────────────────────────────────────────┐
│  3. TERMINAL SERVER sends "your_turn" to Eleanor's client   │
│     → JSON: PlayerView + turn_prompt                         │
└──────────────────┬────────────────────────────────────────────┘
                   │
┌──────────────────▼──────────────────────────────────────────┐
│  4. PLAYER types: "shoot the ghoul with my revolver"        │
│     → Client sends raw text to server                        │
└──────────────────┬────────────────────────────────────────────┘
                   │
┌──────────────────▼──────────────────────────────────────────┐
│  5. ACTION GRAMMAR parses → structured action              │
│     → intent: attack, target: ghoul, tool: .38 revolver    │
│     → mechanics: [{combat: firearms, target_id: ghoul}]      │
└──────────────────┬────────────────────────────────────────────┘
                   │
┌──────────────────▼──────────────────────────────────────────┐
│  6. COMBAT ENGINE resolves (local, deterministic)             │
│     → roll: 34, hit, 8 damage, ghoul wounded, ammo 5/6      │
└──────────────────┬────────────────────────────────────────────┘
                   │
┌──────────────────▼──────────────────────────────────────────┐
│  7. EVENT BUS publishes: SOUND event (gunshot, noise=4)    │
│     → Propagates: basement → ground_floor → upstairs          │
│     → Samuel (upstairs) receives audible event              │
│     → Martha (exterior) receives nothing                    │
└──────────────────┬────────────────────────────────────────────┘
                   │
┌──────────────────▼──────────────────────────────────────────┐
│  8. KEEPER DIRECTOR updates intensity                       │
```

## 7. Testing Strategy

Each module gets a `test_<module>.py` following v2.2's pattern:

```python
# test_director.py
from src.director import KeeperDirector, DirectorState

def test_build_up_to_peak():
    d = KeeperDirector({"peak_threshold": 0.7})
    d.pc_intensity["eleanor"] = 0.8
    d.update({"characters": {"eleanor": {"hp_delta": -5}}})
    assert d.state == DirectorState.SUSTAIN_PEAK

def test_peak_fade_to_relax():
    d = KeeperDirector({"peak_threshold": 0.7, "relax_duration": 5})
    d.state = DirectorState.PEAK_FADE
    d.global_intensity = 0.3
    d._transition_state()
    assert d.state == DirectorState.RELAX
    assert d.state_timer == 0
```

Integration tests in `test_integration.py`:
- 3 players, 3 scenes, different paces, 10 turns

## 9. Open Questions

1. **WebSocket vs SSH vs Local Pipe?** WebSocket enables browser terminals. SSH is simpler for power users. Local pipe for single-player testing.

2. **NPC AI: scripted or LLM-driven?** Proposed: scripted state machine (Idle → Suspicious → Hostile → Fleeing) with LLM narrating transitions. Not full LLM autonomy.

3. **Player authentication?** Simple token-based for now. OAuth later if needed.

4. **Voice integration?** Out of scope for v3.0. Text terminals only.

## 10. Conclusion

This architecture offloads everything possible from the LLM to deterministic engine systems. The LLM receives:
- Structured scene state (~800–1500 tokens)
- Director guidance (1 sentence)
- Belief filters (tag list)
- Event summaries (1 line each)

And returns:
- Narration
- Private narrations
- State delta

The engine handles pacing, memory, synchronization, procedural generation, and cross-scene effects. The LLM focuses exclusively on creative prose.

**Next step:** Validate v2.2 in the field. Once `test_engine.py` passes and a full mock session completes, begin Phase 1 implementation (`action_grammar.py` + `turn_manager.py`).
