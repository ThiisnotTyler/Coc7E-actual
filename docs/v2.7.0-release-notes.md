# CoC 7e LLM Keeper — v2.7.0 "The Lobby Update"

Release notes, July 20, 2026. Covers v2.6.0 -> v2.7.0 (startup lobby, local
chronicle, latency knobs). All changes verified offline: test_engine.py 158
checks + test_charcreate.py 64 checks, both ALL TESTS PASSED, plus
fresh-extraction verification of the shipped zip.

## 1. What this release is

v2.7.0 answers two field questions at once: "why do I pay flagship prices to
walk down a hallway?" and "why does starting a game feel like editing a config
file?". The timing log said solo turns on the heavy tier cost 199-371
seconds. The session start had no menu at all. This release puts a lobby in
front of the game and a diet behind it.

## 2. Field findings (measured, not guessed)

Benchmark: `py test_latency.py`, maintainer's connection, July 19-20, 2026.

| Model | Tier | Wall time | Notes |
| --- | --- | --- | --- |
| kimi-k2.6 | default | 55.4 s | clean on first attempt, 1,094 chars of narration |
| kimi-k3 | heavy | 371.0 s total | initial 174.6 s -> 140 chars, invalid JSON; strict-retry 196.4 s -> ok |

The k3 initial attempt burned its 4096-token budget on hidden reasoning and
emitted almost nothing. The 8192-token strict-retry succeeded — the ladder
worked, but the first attempt was a paid, 175-second loss we could see coming.

## 3. New in v2.7.0

### 3.1 Scenario selection screen (startup lobby, screen one)

`python -m src.main` with no `--scenario` scans `data/scenarios/` and shows a
numbered menu: title, era, expected sessions, one-line hook, and a
`[save: turn N]` resume marker. `--scenario <path>` bypasses it completely
(scripting, CI). Redirected stdin (headless) never prompts — it resolves the
legacy default, the-haunting. Knob: `"game": {"startup_menu": false}`.

### 3.2 Character selection screen (lobby, screen two)

Fresh campaigns (no save) list the roster — name, occupation, age, top three
skills — and accept comma-separated picks (`1,3`), `all`, `pregens`, or `new`
(the 7e wizard runs mid-menu and the grown roster is re-listed). Resumed
saves skip the screen; the save owns the party.

### 3.3 Local folder chronicle

The offline equivalent of the Google Docs save system. Same interface
(`append` / `flush` / `get_last_paragraphs`), same entry format, zero network
calls, no google imports. One markdown file per scenario under `chronicle/`;
the keeper re-points it automatically when a scenario loads. Config:

```json
"chronicle": {"backend": "local", "folder": "chronicle", "batch_size": 5}
```

`"google"` keeps the Docs path (the `google_docs` section still drives it);
`"off"` disables. A config with no `chronicle` section behaves exactly as
pre-v2.7 — old configs upgrade cleanly. Shipped default: **local**.

### 3.4 Latency knobs

- `llm.compact_prompt` (shipped: `true`) — compact JSON separators in every
  prompt block. ~10% fewer prompt characters per turn; the mock client parses
  both forms (pinned by tests).
- `llm.extra_body` (shipped: `{}`) — merged into every
  `chat.completions.create` call. Provider-specific switches (reasoning
  effort, cache hints) with zero code changes.
- `llm.max_output_tokens_heavy` (shipped: `8192`) — the heavy tier starts the
  retry ladder at its own base budget. The measured success point for k3 was
  8192; starting there skips the known-too-short 175s first attempt. The
  default tier's ladder is untouched (4096 -> 8192 -> 16384).
- Shipped `llm.heavy_escalation` is now `"combat"`: heavy only when combat is
  declared. Solo exploration stays on k2.6 at ~48-55s a turn. The CODE
  default remains `"individual"` — configs without the key keep legacy
  behavior (pinned by the escalation matrix test).

### 3.5 Second shipped scenario: The Tallow Chapel

A hilltop chapel outside Arkham renders its own candles; the choirmaster has
been missing nine days. Two sessions, four locations, two NPCs (one willing
to talk, one very much not), three clues, one countdown clock. It exists to
prove the lobby — and to be the reference example for the scenario-authoring
table in the README.

## 5. Upgrade guide

Same as v2.6.0: extract, merge the inner `coc7-keeper` folder over yours
(Replace All), activate the venv, run both suites. Your `config/api-key.json`,
`saves/`, and `data/investigators.json` are never in the zip and survive the
merge. **One config action worth doing by hand:** if you merged over an old
`config/settings.json`, your old file wins the merge — copy the new
`chronicle` block and the `llm` knobs (`heavy_escalation`, `compact_prompt`,
`max_output_tokens_heavy`, `extra_body`) in from the shipped
`config/settings.json` if you want them. Old settings files run fine without
them (code defaults are backwards compatible).
