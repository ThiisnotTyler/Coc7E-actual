# CoC 7e LLM Keeper — v2.7.2 "The Commitment Rule"

Release notes, July 20, 2026. Covers v2.7.1 -> v2.7.2 (object attacks +
committed-action resolution). Verified offline: test_engine.py 190 checks +
test_charcreate.py 64 checks, both ALL TESTS PASSED, plus fresh-extraction
verification of the shipped zip. Regression tests preceded every fix.

## 1. The field log

First session after v2.7.1 (the-haunting, solo):

- Turn 2: *"attempt to breach the door with the shotgun"* -> a full turn of
  atmospheric setup ending *"The trigger waits. The outcome hangs on this
  single blast."*
- Turn 3: the player confirms — *"blast the door."* -> a SECOND setup beat:
  *"His finger tightens on the trigger... You pull the trigger. What do you
  do?"*

Two declarations, zero dice, no resolution. The player's framing is exactly
right: when you tell a DM you commit to an action, it just happens — they
describe what you did, the outcome, and the side details.

## 2. Root causes

1. **The verb net had no breach.** `breach`, `blast`, `aim`, `smash`,
   `kick down` matched nothing in `_preroll`, so both turns carried empty
   DICE RESULTS.
2. **Doors aren't characters.** Even matched combat verbs looked for a
   CHARACTER target via `_find_target`; a door or padlock produced only a
   "no reachable target" note.
3. **No commitment rule.** v2.7.1's "setup-only for un-rolled risky actions"
   rule, applied mechanically, produces an infinite wind-up when the model
   also forgets `dice_requests`. Nothing told the model that a confirmed
   action resolves NOW.

## 3. Fixes

- **Wider combat verbs**: blast, breach, aim, smash, fire, kick down,
  break down, force open — word-boundary regex, so `campfire` stays safe.
- **Object attacks**: when the action names an inanimate (door, lock,
  latch, window, hatch, padlock, deadbolt, barricade, chain, handcuffs,
  bulkhead) and no NPC is named, the engine rolls: firearm skill if a gun
  is in hand and the phrasing is ballistic (shotgun -> Firearms_Rifle_Shotgun,
  else Firearms_Handgun), otherwise raw STR. Result carries an `object` tag
  shown at the table. Named NPCs keep full combat-engine routing (name
  beats object); the nearest-NPC fallback for bare "shoot" is preserved.
- **The commitment rule** (system prompt): a committed action resolves in
  the SAME narration — the act, the outcome from DICE RESULTS, the side
  details. Never two setup beats in a row.
- **`pull the trigger` counts as a roll affirmation** for pending
  dice_requests.
