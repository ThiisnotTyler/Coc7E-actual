## What was added

- `test_items.py` — dedicated hostile test suite for the item registry.
- Test infrastructure inside `test_items.py`:
  - `make_item_fixture()` — reusable fixture builder with two players, one NPC, three+ connected locations, duplicate weapons, ammo, keys, locked/unlocked containers, consumables, light sources, hidden items, world objects, and malformed items.
  - `audit_item_registry()` — invariant checker detecting missing IDs, dual owner/location, multiple owners, equipped IDs outside inventory, negative quantities/ammo, invalid conditions, duplicate IDs, and bad container/object references.
  - `round_trip_save_load()` — save/load canonical-state comparison harness.
  - `run_commands()` — deterministic local meta-command transcript harness.
  - `legacy_fixture()` — synthetic v2.7.x save migration builder.
  - Mock-client call tracking via `MockKeeperClient.calls` for no-LLM assertions.

## Defects found and fixed

1. **Reload silently cleared jams.** Fixed: `reload` no longer sets `condition = "intact"`.
2. **Reload had no ammunition type check.** Fixed: added `ammo_type` to `ItemTemplate` and compatibility check in `CoCKeeper._meta_command`.
3. **Reload did not refresh the transient weapon view.** Fixed: `char.refresh_weapon_view()` after a successful reload of the equipped item.
4. **`use` on consumables did nothing.** Fixed: decrements `quantity`, removes item when depleted.
5. **Equipped items could be dropped/given.** Fixed: `drop` and `give` now require unequip first.
6. **Save/load duplicated equipped weapons.** Root cause: `Character.to_dict()` serialized the transient `weapon` field, and migration recreated it on every load. Fixed: exclude `weapon` from `to_dict()`; migration no longer overwrites an existing `equipped_item_id`.
7. **Legacy migration collapsed all duplicate same-name inventory entries into the equipped instance.** Fixed: only the first matching entry is folded; additional same-name entries become independent instances.

## Known limitations after v2.8.0.1

- **Ammunition quantity is interpreted as individual bullets.** One `ammo_box` with `quantity=6` reloads a six-shooter fully; `quantity=1` adds one bullet. This is the intended convention, but it differs from some tabletop abstractions where one box equals one reload.
- **Containers have no contents system.** `open` toggles state only; items cannot yet be placed inside or retrieved from containers.
- **Hidden items are protected by command absence.** There is no generic "look around" command, so hidden items cannot be revealed accidentally. v2.8.1's room-view layer will make visibility explicit.
- **Consumable effects are narrative, not mechanical.** `use` decrements quantity but does not apply HP/SAN/etc. effects; those still require engine events or LLM narration.
