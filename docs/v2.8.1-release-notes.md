# v2.8.1 Release Notes — "Room Truth and Offline Movement"

**Phase:** Persistent Campaign Engine Roadmap, Phase 2  
**Baseline:** v2.8.0/v2.8.0.1 "Canonical Items and Objects (Registry Proving Ground)"

The doctrine, applied to space itself: **the engine owns truth; the model owns
voice.** Rooms stop redecorating themselves, ordinary walking stops costing
API calls, and the narrator is handed a deterministic view of exactly what is
in the room — no more, no less.

## What changed

### Authored room descriptions (scenario schema)

`locations.<id>` accepts new optional fields: `description`, `first_visit`,
`revisit`, `details`, `lighting`, `tags`. All default empty, so every
pre-v2.8.1 scenario and save loads unchanged; rooms without authored text
fall back to the old behavior.

### `src/room_view.py` — the deterministic room view

One module builds what a room *is* from engine state: authored description
(first-visit vs revisit, per character), object state, visible items, visible
characters (with readied items marked), lighting, details, and valid exits.
Hidden items, hidden objects, hidden exits, and clue data never appear — not
on the screen, and not in the LLM prompt.

### Local observation commands

`observe`, `look`, `look around`, `examine room` print the deterministic room
view. They never call the LLM and never consume a narrative turn.

### Offline movement

Pure movement declarations — `go to`, `enter`, `leave`/`go back`/`return`,
`head to`, `walk to`, `step into`, and similar forms — resolve locally:
destination matching, graph validation, exit-state checks, occupant and
current-scene updates. Ordinary movement makes **zero API calls** and
consumes no narrative turn. Invalid moves are refused with the valid exits
listed. Anything that is not a clean movement declaration falls through to
the normal Keeper path untouched — this is not a command parser.

### Exit state

Connections accept `state`: `open`, `closed`, `locked`, `blocked`, `hidden`,
`destroyed`, plus `key_id`, `object_id`, and the documentary `one_way` flag.

- `locked` exits open permanently when the mover carries the matching key —
  the engine performs the unlock, and a linked door object (`object_id`) is
  kept consistent automatically.
- `blocked` and `hidden` exits refuse movement; `hidden` exits are also
  invisible in room views and prompts.
- `destroyed` exits are passable (the barrier is gone) and flagged.
- One-way passages are expressed by defining the connection on one side only.

### Hybrid LLM escalation

Entering an ordinary stable room is local. Entry escalates to the LLM when it
involves: a visible NPC, a hazard/trap-tagged room, a SAN-pressure-tagged
room, a first-time visible-clue reveal (`"visible": true` on a clue — the
engine stamps it discovered), a front trigger at the current clock, or a
timeline event pinned to the turn. On escalation the engine has **already**
decided what happened — the character is moved, the LLM receives a
`MOVEMENT EVENTS` block and only narrates. If the model's state_delta tries
to move that character elsewhere, the engine re-asserts its own move.

### Prompt integration

The turn prompt now carries `ROOM VIEW` (the deterministic view of the
current scene) alongside the existing blocks, and `EXITS` lists only visible
exits. The system prompt's new ROOM TRUTH section forbids inventing exits,
items, occupants, or room features, and a weapon is "in hand" only when
marked readied.

### Scenario item placement

`scenario.json` accepts `placed_items`: `[{"template": id, "location": room,
"owner": char, "quantity": n, "name": ..., "tags": ["hidden", ...]}]` — the
missing piece for authored gear on the floor.

### Save/load

Saves now round-trip the authored location fields, mutated connection state
(unlocked doors stay unlocked), per-character visited rooms (first-visit
memory), and discovered clue ids. Old saves load unchanged.

## Regression coverage

50 new deterministic checks in `test_engine.py` prove: observe/look call no
LLM and consume no turn; ordinary movement calls no LLM and consumes no turn;
invalid movement lists valid exits; locked/blocked exits prevent movement;
destroyed/open/closed exits behave correctly; hidden exits are invisible and
unmatchable; one-way rooms offer no way back; first-visit and revisit text
differ; overlays include visible items, objects, and characters; hidden and
locked content never leaks; movement updates occupants and current scene;
carried keys unlock exits permanently; NPC-occupied rooms escalate exactly
once with the engine still owning the move; movement events and room view
reach the prompt; room truth survives save/load; a full scripted session
(help → observe → move → observe → locked refusal → key → escalation →
save/load) runs clean; the worldbuilding guide matches the shipped scenario.

## Known limitations

- **Clue triggers are still informational.** `skill`/`difficulty` on clues
  are stored for v2.8.4; only the `visible: true` room-reveal hook is live.
- **Containers remain shallow** — `open` toggles state; no contents system.
- **`exit` still quits the game.** Use `leave`, `go back`, or `return` to
  leave a room (documented in the worldbuilding guide's Common Mistakes).
- **Active-combat, major object-state reveals, and private perception are
  escalation hooks only** — they land with their roadmap phases (v2.8.2+).
- **Front triggers only escalate when the clock already sits on a trigger
  value**; noise→front advancement is v2.8.2.
