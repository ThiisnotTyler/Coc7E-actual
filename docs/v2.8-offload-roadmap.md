# v2.8 Offload Roadmap — What Python Should Own Next

*Written at v2.7.6. Strategic answer to: "what else can we cleverly offload to
Python to increase game speed, functionality, consistency, AI knowledge, and
game difficulty, without increasing token costs — and without becoming
over-reliant on any one hosted API?"*

## The cost anatomy (measured, not guessed)

From `logs/llm_timing.jsonl` with the v2.7.5 meter:

| Component | Share of turn cost | Lever |
|---|---|---|
| Input tokens (system prompt + state + declarations) | ~10% | already cheap; context caching is hitting |
| Output tokens — visible narration | small | keep as-is |
| Output tokens — **hidden reasoning** | **~90%** | fewer API turns; reasoning budget |

A k2.6 turn ≈ $0.02, a k3 turn ≈ $0.04. The expensive part is not what the
model *says* — it is what the model *thinks* before saying it. Every offload
below is ranked by how many API turns (or how much reasoning) it removes,
never by how much prompt text it saves: prompt size is nearly free.

## Ranked offloads

### Tier 1 — pure wins (no LLM involvement at all)

1. **Zero-LLM movement turns** (`llm.offline_movement: true`).
   "I go to the kitchen" needs no narration engine: the engine knows the map,
   moves the character, prints the room's static description + exits +
   whoever is present. Eliminates the most frequent API turn of all.
2. **`status` / `sheet` meta-command.** HP/SAN/skills/gear printed locally.
   Players currently burn a turn asking the Keeper what the engine knows.
3. **Static room descriptions** served from `scenario.json` on entry;
   the LLM only re-describes a room when state changed (corpse added, door
   blown open). Consistency goes *up*: the kitchen stops redecorating itself.

### Tier 2 — consistency & difficulty (engine remembers, engine adjudicates)

4. **Object state table.** The lock that was blown off its door stays blown
   off. Engine-owned `objects: {id: {state, room}}`, mutated by combat/force
   results, injected into the prompt as one cheap line. Kills the classic
   LLM amnesia where a destroyed obstacle resets next scene.
5. **Facts ledger.** Every `state_delta` fact the LLM emits gets appended to
   a local ledger; the prompt carries the ledger, not the model's memory.
   AI knowledge becomes cumulative and auditable.
6. **Clue triggers.** Scenario clues carry keyword/location triggers; when a
   search roll succeeds in the right place the engine stamps `clue_found`
   and hands the LLM the exact clue text to reveal. Difficulty by design:
   clues are earned by dice, not donated by prose.
7. **Noise → front clocks.** Gunshots, forced doors, screaming: the engine
   increments a noise clock; at thresholds it advances scenario "fronts"
   (cultists armed, Lusk flees, police called). This is difficulty that
   *escalates deterministically* with player recklessness — the thing a
   narration model will never consistently enforce.
8. **Fumble SAN checks.** A fumbled combat roll in a Mythos scene triggers
   the engine's SAN ladder automatically. The 7e rulebook already lives in
   code; use it.

### Tier 3 — spend less thought per turn

9. **Reasoning budget via `extra_body`.** Moonshot/OpenAI-compatible
   endpoints accept provider-specific params; `llm.extra_body` already
   passes through. Measure a capped-reasoning turn vs current (expect the
   ~90% output share to collapse) and ship the best default. This is the
   single biggest cost lever on the board.

## Provider independence (the self-hosted future)

Already true today:

- `provider: custom` + `base_url` runs against Ollama / LM Studio / vLLM —
  see `docs/LLM-PROVIDERS.md`.
- `json_mode: false` knob for models without structured output.
- The three-strike JSON-repair ladder absorbs weak local models.
- `--mock` runs the full engine offline for CI.

Hardening list (do before a local-model launch):

- **Short prompt variant** (`config/system-prompt-small.txt`): the 4K-token
  system prompt is tuned for frontier models; a 7B local model needs the
  same rules in ~800 tokens. Rules, schema, three examples — nothing else.
- **Verify the reasoning-budget knob degrades gracefully** on providers
  that ignore `extra_body` (it must be a no-op, not an error).
- **Keep the dice_requests channel optional**: if a local model never emits
  it, the preroll net already covers the common verbs — the game degrades
  to v2.7.1-style play, not to silence.

## Never offload

The LLM keeps: narration voice, NPC dialogue, option generation, long-tail
interpretation of weird player declarations, and `state_delta` judgment.
That is the game. The engine owns truth; the model owns voice. Every item
above moves more *truth* into the engine — none of them move *voice* out.
