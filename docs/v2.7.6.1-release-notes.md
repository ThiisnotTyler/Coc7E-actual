# v2.7.6.1 Release Notes — "The Truth Firewall"

**Phase:** Persistent Campaign Engine Roadmap, Phase 0  
**Baseline:** v2.7.6 "The Spoiler Channel"

## What changed

### The LLM no longer gets direct write access to canonical truth

v2.7.6 still allowed model-produced `state_delta` content to assign many core character fields directly. That violated the campaign-engine rule: **the engine owns truth; the model owns voice.**

This patch introduces `src/state_validator.py`, a validation layer between the model and world state.

The model may still return:

- narration
- private narrations
- dice requests
- plot-point proposals
- bounded front-clock updates
- validated scene transitions
- sound-event proposals
- safe narrative character fields such as position, declared action, personal log, and extra notes

The model may **not** directly assign engine-owned fields such as:

- HP, SAN, MP, Luck, or characteristics
- skills or checked skills
- weapon, weapon instances, inventory, or key items
- location
- wounds, dying, unconsciousness, or insanity
- Cthulhu Mythos
- character identity fields

Rejected writes are logged in debug mode and never crash the turn.

### Movement is validated against the actual map

Scene transitions now must reference:

1. a known character,
2. a known destination, and
3. a destination connected to that character's current location.

The model can no longer teleport someone by writing a location directly into `state_delta.characters`.

### Front clocks are clamped

Model-suggested front updates must:

- reference an existing front,
- be numeric, and
- remain inside `0..max`.

Phase 3 will replace model-driven clock changes with deterministic trigger-driven updates. This release adds the safety rail first.

### Weapon ammunition persists through unequip/equip

Characters now carry persistent `weapon_instances` keyed by weapon display name.

Before this patch:

1. fire two shells,
2. unequip the shotgun,
3. equip it again,
4. receive a fresh catalog copy with full ammunition.

Now re-equipping retrieves the same weapon instance. Ammunition and malfunction state survive unequip/equip and save/load. The full item/object registry arrives in v2.8.0; this is the compatibility bridge.

### Prompt serialization includes carried gear

`Character.to_active_format()` now includes inventory alongside the equipped weapon, reducing the chance that the model narrates gear the character does not actually possess.

## Regression coverage

New tests prove that:

- the LLM cannot directly set HP, SAN, location, inventory, or weapons;
- unapproved character fields are rejected;
- unknown characters cannot receive state changes;
- front clocks clamp to their configured maximum;
- scene transitions must follow the location graph;
- plot points and sound events are sanitized;
- unknown top-level `state_delta` fields are rejected;
- weapon instances seed from equipped weapons;
- ammunition persists through unequip/equip;
- ammunition persists through save/load.

## Compatibility

Existing v2.7.x saves migrate on load:

- equipped weapons seed `weapon_instances`;
- empty inventories still seed from equipped weapons;
- old saves without `weapon_instances` load normally.

The legacy `state_delta` shape is still accepted, but only after validation. This keeps current provider behavior compatible while closing the direct-mutation hole.

## Known gap: scenery consistency

The Truth Firewall does not yet prevent the model from re-describing a room differently each time it is observed. Engine-owned truth covers HP, SAN, gear, location, and clocks, but not the narrative details the LLM has already rendered. A future **rendered-details ledger** will let Python remember what has been described and feed those facts back to the model, eliminating scenery hallucination. Once that ledger is in place, already-rendered and pre-rendered location details will be summarized into shortform before being injected into the prompt to limit token growth.
