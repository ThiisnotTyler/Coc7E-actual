# v2.8.0 Release Notes — "Canonical Items and Objects"

**Phase:** Persistent Campaign Engine Roadmap, Phase 1  
**Baseline:** v2.7.6.1 "The Truth Firewall"

## What changed

v2.8.0 replaces the v2.7.6.1 string-inventory and weapon-instance bridge with a persistent item and object registry. Gear, keys, documents, containers, and room scenery are now first-class campaign state instead of display names in a list.

### Canonical item registry

- New `src/items.py` defines:
  - `ItemTemplate` — catalog definition for a kind of item.
  - `ItemInstance` — a persistent physical item with owner, location, ammo, condition, and state.
  - `WorldObject` — persistent room scenery such as doors, containers, and furniture.
- New global catalog `data/items.json` ships weapon, ammo, tool, key, document, consumable, and light-source templates.
- `CoCKeeper` owns `item_templates`, `item_instances`, and `world_objects` registries.
- `Character.equipped_item_id` replaces the raw `Weapon` field. `Character.weapon` remains a transient compatibility view built from the equipped instance so existing combat code needs minimal changes.
- `Character.inventory` is now a list of item instance IDs.

### New and expanded meta-commands

All commands resolve locally and never consume a turn or call the LLM:

- `inventory` / `inv` — list carried and equipped items with ammo/condition.
- `equip <item>` — ready a carried weapon or tool.
- `unequip` — put away the equipped item.
- `take <item>` — pick up an item in the room.
- `drop <item>` — place an item on the ground.
- `give <item> to <character>` — transfer an item to another investigator in the same room.
- `reload <weapon>` — refill a firearm from carried ammunition.
- `open <container>` — open a container or door (respects `locked` + `key_id`).
- `look at <thing>` / `examine <thing>` — inspect an item, object, or person.
- `use <item>` — deterministic handler for light sources, consumables, and tools.
- `help` / `list` / `?` — print every available in-game command.

### Combat integration

- Firearm ammunition is consumed from the equipped `ItemInstance`.
- Malfunctions update the instance `condition` to `jammed`.
- Two investigators with the same weapon template maintain separate ammo and condition.

### Save compatibility

- v2.7.x and v2.7.6.1 saves migrate on load:
  - legacy `weapon` dicts become item instances,
  - string inventory entries become item instances,
  - `weapon_instances` become carried item instances,
  - duplicates between equipped weapon and inventory strings are collapsed.
- New saves include `item_instances` and `world_objects` registries.

### Prompt contract

- `config/system-prompt.txt` now includes an `ITEMS AND OBJECTS` section reminding the model that item creation, movement, equipping, reloading, opening, and destruction are engine-owned.
- `equipped_item_id` is added to the Truth Firewall's engine-owned fields.

## Regression coverage

`test_engine.py` plus the new v2.8.0.1 `test_items.py` (131 checks) prove that:

- two characters with the same weapon template have separate instances and ammo,
- ammo persists independently per character and survives unequip/equip/save/load,
- `take`, `give`, `reload`, `open`, `look at`, `examine`, `use`, and `help`/`list` resolve locally and never call the LLM,
- locked containers require the matching key,
- the item and object registries round-trip through save/load,
- v2.7.x legacy saves migrate into the new registry without collapsing legitimate duplicates,
- hostile `state_delta` mutations against `inventory`, `equipped_item_id`, `weapon`, `item_instances`, and `world_objects` are rejected,
- `use` on a consumable decrements quantity and removes the item when depleted,
- equipped items cannot be dropped or given until unequipped,
- reloading does not silently clear a jam and respects ammunition type compatibility.

## v2.8.0.1 — Registry Proving Ground

After acceptance, a dedicated hardening pass (`docs/CoC7-Keeper-v2.8.0-Post-Acceptance-Testing-Program.md`) added `test_items.py` and fixed the defects listed above. The v2.8.0 item registry is now considered proven.
